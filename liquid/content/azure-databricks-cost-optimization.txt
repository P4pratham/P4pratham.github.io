Processing multi-terabyte daily telecom feeds on Azure Databricks can quickly explode cloud compute costs if cluster configurations are left unoptimized. Here are the core architectural patterns I implemented at Amdocs for Three UK to streamline cost efficiency.

### 1. Auto-Scaling with Single-Node & Spot Instances

For batch ETL jobs running during off-peak hours, leveraging Azure Spot VMs for worker nodes can reduce compute costs by up to 70-80%. Combined with tight auto-scaling thresholds, clusters scale down immediately when task queues drain.

### 2. Delta Lake Liquid Clustering vs Z-Ordering

Traditional partitioning on high-cardinality keys leads to the small file problem. By switching to Delta Lake Z-Ordering or Liquid Clustering on frequent join keys (like Account ID and MSISDN), scan volumes drop significantly, leading to faster execution times and lower DBU consumption.

### 3. Key Takeaways

- Set aggressive auto-termination timeouts (e.g. 15-20 minutes) on interactive developer clusters.
- Enforce Unity Catalog table ACLs to prevent redundant compute query scans.
- Use Delta Live Tables (DLT) for automated pipeline maintenance and data quality checks.
